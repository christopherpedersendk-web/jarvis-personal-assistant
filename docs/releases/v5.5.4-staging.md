# 5.5.4 — OpenClaw-integration til staging

Kandidat, ikke produktionsdeployment. Schema 1/readableFrom 0. Eksisterende tags bevares; aktuelt remote skal kontrolleres før publicering.

- Direkte OpenClaw health og web_search samt eksisterende JARVIS-adapter er faktisk verificeret. Interne markører fjernes fra viste kildetitler; gatewayens 60-kaldsgrænse bliver et monotont timevindue med konkret 429 og ingen retry. Den allerede installerede immutable gateway opdateres ikke af appkoden alene.
- Ny opt-in native OpenClaw/Chromium-læser bruger en netværksløs ikke-root container og begrænset DNS-pinnet offentlig GET-broker. Faktisk Proshop-læsning, kontrollerede afvisningsprøver, anvendt isolation og stop/fjernelse er dokumenteret. Ingen generisk browserwrite, login, kontakt, betaling eller ordre tilføjes af læseren.
- Eksisterende offline backupbundle understøtter eksplicit udvalgte konfigurationsfiler. Faktisk krypteret ekstra-runtime-restore verificerede 707 filer; automatisk backupplan og samlet offlinekonsistens ændres ikke.
- Ejerens Discord-test-only-opgave afslørede manglende beskyttet kontraktvalg og fejlagtigt unknown før Docker-start. Rettet og reproduceret med præcise testbytes/base/diff i separat worktree og faktisk Docker. Originalopgaven er bevaret, ikke genafspillet eller publiceret.

Læs [acceptregistret](../next/acceptance-register.md) og de separate evidensfiler. Ingen hel milestone lukkes. Fuld gæste-/adresse-/2900-checkout og ejerens udvikling→draft-PR er fortsat særskilte acceptkriterier. Ejeren har valgt gæstecheckout, men adresseoverførsel kræver et konkret revisionsbundet review.

Før en senere autoriseret installation: forbered fastlåste valgfrie voice-/semantic-afhængigheder i staging; verificér model- og imagehashes. Native browser kræver den dokumenterede offentlige runtime, Node og præcise lokale image-ID. Hverken native browserflag, self-releasegodkendelse eller produktionsbackupplan aktiveres af denne release.
