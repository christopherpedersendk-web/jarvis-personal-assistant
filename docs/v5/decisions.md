# v5 technical decisions

| ID | Decision | Reason and verification still needed |
|---|---|---|
| D-001 | Develop on `feature/v5-foundation` based on exact v4.9.1 SHA | Both main and v4.9.1 matched; preserves published v4.9.0 tag |
| D-002 | Keep the existing modular JavaScript/Node application and modernise incrementally | Existing 149 tests pass; avoid a speculative framework or service split |
| D-003 | Bevar JSON/skema 1 med én serialiseret transaktionsgrænse, isolerede kladder, fsync og privat to-fil-journal | Den hidtidige måling er 72 KB / enkeltbruger og begrunder ikke i sig selv SQLite. Ny durable-store-kloning og journal skal måles på denne kandidat. Private/public settings kan gendannes som par, men er ikke atomiske renames sammen. Forudsætter én applikationsskriver; ingen garanti mod vilkårlige samtidige eksterne filredigeringer. Ukendt publicering blokerer nye ændringer. |
| D-004 | Ægte semantik lokalt i isoleret CPU-worker; ingen automatisk netværksdownload eller cloud-embeddings | Fast multilingual-E5-small-revision og SHA-256 for model/tokenizer; Transformers.js 3.8.1. Kun eksplicit lokal konfiguration aktiverer modellen, lexical fallback er altid tilgængelig. CI anvender kun syntetiske data og offentlig model; 80 relevante +16 sikkerhedsspørgsmål er låst før målingen. Kvalitet er ikke godkendt før faktisk modelkørsel. |
| D-005 | App navigation uses query-string views and browser history | Deep links work through the existing static-server root without changing deployment paths; test keyboard/back/forward |
| D-006 | Preserve confirmed attendance separate from Google calendar events | Hard user requirement from v4.9 and v5 handover |
| D-007 | Preserve Nemlig add-only, click-bound write model; consume one-use in-memory click-intention token tied to proposal revision/additions | A web request cannot cryptographically prove physical presence, and an external read/write has a real race; no blind retries of unknown outcomes |
| D-008 | Distinguish personal tasks, automated jobs, follow-ups and calendar events | `personal-tasks.mjs`, `task-engine.mjs`, `follow-up-cases.mjs`, `capacity-planner.mjs` use separate contracts; prevents falsely treating a planned task as an external action |
| D-009 | Decline automatic v4 code rollback after schema 1 migration | Older code could silently drop newer fields. The deployer records `rollback-blocked` for administrator review; no production change authorised |
| D-010 | Keep Google Calendar read-only with explicit selection and source coverage | Local selected calendar ID and last successful read, no event creation or household attendance inference |
| D-011 | Show one memory creation entry point with a mode switch for legacy notes versus structured claims, while retaining both data stores | Prevent duplicate settings editors without a risky implicit rewrite of historic records. Exact sources, revisions and confirmation rules remain intact. A future unified *backend* record model needs migration and is still pending; the two forms are never simultaneously visible. |
| D-012 | Pin official Playwright `v1.64.1-noble` test container and exact npm version, non-root UID 1001 | Ubuntu's apt mirror timed out under `--with-deps`; without apt the hosted runner lacked GTK4/GStreamer/WebKit libraries. The [official Playwright CI guidance](https://playwright.dev/docs/ci) supplies this container pattern. This changes only synthetic CI, not production Docker privileges. **Actual Chromium and WebKit launches remain required** |

| D-013 | Bind projektbeviser til komplet kildehash, separat fra modellens begrænsede kontekst | Hash: højst 16 MiB/fil, 64 MiB/2.000 poster; modeltekst: 45 KB/fil, 50 filer/180 KB; testkopi: 2 MiB/fil, 300 filer/8 MiB. Ufuldstændig testkopi giver unavailable, aldrig passed. VCS, node_modules og private konfigurationsfiler sendes ikke til modellen. Legacy rollback uden bundet manifest kræver manuel gennemgang. |
| D-014 | Journalfør intention før effekt; mistet resultatsave betyder ukendt, ikke sikker genudførelse | Job med kendt response-ID genoptager polling på samme ID. Jobs uden sikkert ID, unknown levering, delvis Nemlig-overførsel og ukendte projektfiler gentages ikke. Retry/pause/missed-run-policy er eksplicit. Kun lokale checkpoints kan genforsøges uden at genudføre ekstern effekt. |
| D-015 | Beskyt semantiske top4; suppler kun med et distinkt, fuldt leksikalsk match | Første rigtige CI viste at svage, tilfældige ordoverlap fortrængte relevante danske parafraser. Reglen er generisk, ikke spørgsmålsbestemt; fast fixture og 90 %-gate bevares. Nye modeltal er påkrævet før accept. |
| D-016 | Afgrænset bootstrap og cursor-bundet historik; fuld legacy-state-route bevares eksplicit for kompatibilitet | Den normale UI henter ikke hele husstand/opskrift/handlingsjournal ved start. Domæner hentes ved visning; historik20 ad gangen, højst50, stale cursor409. Eksisterende lagrede historikgrænser ændres ikke. Ny før/efter-måling skal binde den anvendte route. |
| D-017 | I dag viser prioriteret overblik; yderligere tællere/drift/historik er sammenfoldet | Dokumentets K2 prioriterer samtale og få relevante forhold. Eksisterende kort/handlinger bevares i “Flere detaljer og historik”; verificerede driftsproblemer vises uden for folden. “Ikke verificeret” er ikke det samme som fejl eller bestået backup. |

Alle beslutninger er reviewbare mod `verification.md`. Udviklingsbranch og draft-PR er ikke godkendelse til merge, release eller installation.
